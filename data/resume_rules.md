# Resume Rules

## Writing Principles

### 1. Result-Oriented
- Every bullet must state what was achieved, not just what was done. Responsibilities describe a job; accomplishments describe a candidate.
- Weak: "Responsible for analyzing donor data." Strong: "Identified 352 lapsed donors averaging $3,044 in lifetime value, enabling targeted re-engagement outreach."
- If a bullet contains no measurable outcome, signal, or impact, rewrite or drop it.

### 2. STAR Structure
- Each bullet should implicitly follow Situation → Task → Action → Result. The result must always be present; the situation can be implied.
- Do not write all four components as separate sentences. Compress them into one tight bullet.

### 3. XYZ Formula
- Default to the pattern: "Under [X condition / at [scale]], [did Y], achieving / resulting in [Z outcome]."
- This is more precise than STAR for single-line bullets. Prioritize Z (the result) — it is the most important element and should never be omitted or vague.

### 4. Concise and Professional
- Use bullet points only. No paragraph prose in experience or project sections.
- Remove hollow adjectives and adverbs: "actively," "effectively," "successfully," "outstanding," "passionate." They add no information.
- Prefer precise, field-specific terminology over generic business language. "Applied window functions for consecutive-streak detection" beats "used advanced SQL techniques."
- Keep each bullet to one to two lines. If it exceeds two lines, split or compress.

### 5. Reverse Chronological Order
- Place the most recent experience and highest degree first within their sections.
- Within a single entry, place the highest-impact bullet first.

### 6. Relevance Matching
- Rank and reorder bullet selection to put the most JD-aligned content at the top of each experience entry.
- The first bullet of the first experience entry is the highest-visibility position on the resume — make it the strongest match to the JD's primary requirement.
- If a bullet is truthful but not relevant to the JD, deprioritize or omit it in favor of a more aligned one from the candidate's pool.

### 7. Truthfulness
- Never fabricate metrics, tools, outcomes, or responsibilities. Every claim must be traceable to the candidate's actual experience or project library.
- If a number is approximate, it may still be used when the source material supports the range (e.g., "~2,900" or "300+").
- Logical consistency is required: numbers must not contradict each other within the same resume.

## Layout and Selection Rules
- Preserve the LaTeX template exactly.
- Keep the resume on one page.
- Make the page feel as full as possible without causing overflow.
- Always select exactly 3 experience entries and 3 project entries.
- Always include Arizona List — Data Analyst Intern as one of the 3 experience entries. Choose the remaining 2 from the other entries based on JD fit.
- Do not invent tools, metrics, responsibilities, or outcomes.
- Do not invent technologies, business context, or impact.
- Prefer ATS-friendly wording while keeping claims truthful.
- Aim for 3 bullets per work experience entry whenever supported by the source material, and allow 4 only when the extra detail is genuinely useful.
- Prefer specific methods, tools, analysis targets, business context, and validated outcomes when supported by the source material.
- Do not fill space with generic, repetitive, or padded wording.
- If the source material does not support more detail, keep the content shorter rather than adding filler.
- Return concise bullets that still fit the one-page layout.
- Do not repeat in the Projects section any work that is already described in an Experience entry. Each section must cover distinct contributions. If a project overlaps with internship work, place it only in Experience and omit it from Projects.
- English JD -> English resume. Chinese JD -> Chinese resume if the template supports it.
- If the JD emphasizes a verified candidate skill, try to align the selected work experience bullets and project bullets toward that theme when the source material genuinely supports it.
- When relevant, surface JD-aligned tools, frameworks, and methods from the candidate's real experience or projects instead of relying only on the Skills section.
- Improve keyword alignment through truthful emphasis, reordering, and wording choices, but do not exaggerate, fabricate, or overstate depth of experience.
- Treat the following as verified candidate skills that may be used in the skills section when relevant to the JD: PyTorch, TensorFlow, NumPy, Pandas, scikit-learn, LangChain, LlamaIndex, Azure, AWS, Power BI, Tableau, Excel, PostgreSQL, SQLAlchemy, matplotlib, geopandas, SQL, Hugging Face, Transformers, RoBERTa, BART, DistilRoBERTa.
- Include these skills selectively based on JD relevance, available resume space, and support from the candidate's experience or project library.
- Do not include every verified skill by default.
- Prefer placing NumPy, Pandas, matplotlib, SQL, PostgreSQL, R under Languages & Analytics when selected.
- Prefer placing PyTorch, TensorFlow, scikit-learn, LangChain, LlamaIndex, SQLAlchemy, geopandas, Hugging Face, Transformers, RoBERTa, BART, DistilRoBERTa under Data Stack & ML Frameworks when selected.
- Prefer placing Azure and AWS under Data Stack & ML Frameworks when selected.
- Prefer placing Power BI, Tableau, and Excel under Languages & Analytics when selected.
